# 52 – المتبقي بعد الفحص الأخير (الدفعتان: الإعدادات/المنطق + ملفات الخرائط)
> قراءة وبحث نصي؛ لم أبنِ المشروع ولم أشغّل التطبيق. «طُبّق» = وجدته في الملفات المرفوعة.

## أولاً: ما تأكدت أنه طُبّق ✅
- **AndroidManifest:** `usesCleartextTraffic=false`، حذف `ACCESS_BACKGROUND_LOCATION`، صلاحيات الخدمة الأمامية، `screenOrientation`، الرجوع التنبؤي، `queries` للتعرف على الصوت، إزالة `foregroundServiceType` من FCM.
- **build.gradle:** `targetSdk = 36`، `appcheck-debug` صار `debugImplementation`، حارس توقيع الإصدار (`GradleException`).
- **MainActivity:** حُذف مصدر الموقع الثالث (`startFusedLocationUpdates`) وصار يستعمل `viewModel.startLocationUpdates()`. **NetworkUtils:** `hasInternetTransport` و`isValidatedNetwork`، و`OfflineQueueManager.isOnline()` يستعملها.
- **الملاحة:** إصلاح قفز المحطات (`routeForIndex` و`lastArrivalAt` وتصفير المتتبع)، ومسافة المنعطف تحت الأيقونة، وكل ما سبق في 38–45.
- **MapScreenContent:** لافتة فشل البلاطات مع «إعادة المحاولة».

## ثانياً: المتبقي (بالأولوية)

### 1) دورة حياة الموقع: لا إيقاف عند الخروج للخلفية (عالية: بطارية + خصوصية)
`MainActivity` لا يملك `onStop` يوقف التحديثات، بينما `MapScreenContent` لا يزال يوقفها فقط عند مغادرة شاشة الخريطة. النتيجة: GPS بدقة عالية يستمر والتطبيق في الخلفية، وفي المقابل يتوقف الموقع عند الانتقال لأي شاشة أخرى (قوائم الفنيين بمسافات قديمة). **مالك واحد = النشاط.**
في `MainActivity`:
```kotlin
private val viewModel: MainViewModel by viewModels()      // إن لم يكن حقلاً أصلاً

private fun hasLocationPermission() =
    PermissionManager.hasPermission(this, PermissionManager.PERMISSION_FINE_LOCATION) ||
    PermissionManager.hasPermission(this, PermissionManager.PERMISSION_COARSE_LOCATION)

override fun onStart() {
    super.onStart()
    if (hasLocationPermission()) viewModel.startLocationUpdates()
}
override fun onStop() {
    viewModel.stopLocationUpdates()          // لا تتبّع والتطبيق في الخلفية (أثناء الملاحة تتولى الشاشة بقاءها مضاءة)
    super.onStop()
}
```
وفي `MapScreenContent` **احذف** `DisposableEffect(Unit) { onDispose { viewModel.stopLocationUpdates() } }`.
> أثناء ملاحة والشاشة مطفأة سيتوقف التتبع بهذا السلوك. إن أردت متابعة الملاحة بالشاشة المقفلة أضف لاحقاً خدمة أمامية من نوع `location` (تحتاج `FOREGROUND_SERVICE_LOCATION` وصلاحية موقع ظاهرة)؛ أما الآن فالتطبيق يُبقي الشاشة مضاءة أثناء الملاحة.

### 2) إفصاح الموقع قبل طلب الصلاحية لم يُضَف (متوسطة، للمتجر والثقة)
`PermissionManager` يوفّر نصاً شارحاً لكنه غير مستخدم قبل `locationPermissionLauncher.launch(...)` (سطر ≈ 233 و671 في `MapScreenContent` وفي `MainActivity`). وفيه خطأ إملائي: «الوصول للـ**صغار** والمعرض» والصواب «للـ**صور** والمعرض». ونص الموقع لا يذكر الملاحة ولا الفزعة.
```kotlin
// PermissionManager.getRationaleForPermission
PERMISSION_STORAGE_IMAGES, Manifest.permission.READ_EXTERNAL_STORAGE ->
    "يحتاج التطبيق لإذن الوصول للصور والمعرض لاختيار الصور وإرفاق السير الذاتية."
PERMISSION_FINE_LOCATION, PERMISSION_COARSE_LOCATION ->
    "نستخدم موقعك لعرض الفنيين والمتاجر القريبة وحساب المسارات والملاحة. لا يغادر موقعك جهازك إلا عند طلبك مساراً عبر الإنترنت أو إرسالك نداء فزعة بموافقتك."
```
```kotlin
@Composable
fun LocationDisclosureDialog(onAccept: () -> Unit, onDecline: () -> Unit) {
    AlertDialog(
        onDismissRequest = onDecline,
        title = { Text("لماذا نطلب موقعك؟") },
        text = { Text(PermissionManager.getRationaleForPermission(PermissionManager.PERMISSION_FINE_LOCATION)) },
        confirmButton = { TextButton(onClick = onAccept) { Text("متابعة") } },
        dismissButton = { TextButton(onClick = onDecline) { Text("ليس الآن") } }
    )
}
// الاستعمال: بدل locationPermissionLauncher.launch(...) مباشرة
var showLocationDisclosure by remember { mutableStateOf(false) }
...  else { showLocationDisclosure = true }
if (showLocationDisclosure) LocationDisclosureDialog(
    onAccept = { showLocationDisclosure = false; locationPermissionLauncher.launch(arrayOf(Manifest.permission.ACCESS_FINE_LOCATION, Manifest.permission.ACCESS_COARSE_LOCATION)) },
    onDecline = { showLocationDisclosure = false }
)
```
وكرر النمط في `MainActivity` (مسار `permissionLauncher`).

### 3) Gradle (متوسطة)
- **`GEMINI_API_KEY`** ما زال في `BuildConfig` (موضعان): يُستخرج من الـ APK. احذف `buildConfigField` وأي استعمال.
- `lint { checkReleaseBuilds = true }` أعده (تعطيله يخفي مشاكل حقيقية). ابدأ بـ `abortOnError = false` ثم شدّده.
- `debug { ndk { abiFilters += "x86_64" } }` لتعمل المحاكيات (الآن `arm64-v8a`/`armeabi-v7a` فقط).
- `kotlinx-coroutines-play-services:1.7.3` ما زال مثبتاً يدوياً؛ انقله إلى `libs.versions.toml` بنفس إصدار بقية coroutines.
- `minSdk = 24` صحيح لأندرويد 7؛ لا حاجة لـ`coreLibraryDesugaring` إلا إن خفّضته إلى 23 (المستند 49).

### 4) Proguard (منخفضة الآن؛ ضرورية عند تفعيل R8)
قواعد `-keep` الشاملة على `com.google.android.gms.**` و`androidx.compose.**` ما زالت (تُبطل التصغير ولا لزوم لها). وغاب `-assumenosideeffects` لإزالة `Log.v/d/i` (بعض السجلات قد تحوي إحداثيات).
```proguard
-assumenosideeffects class android.util.Log {
    public static int v(...);
    public static int d(...);
    public static int i(...);
}
```
احذف سطري gms وCompose. وطالما `isMinifyEnabled=false` فالسجلات ستبقى؛ فاجعل أي سجل فيه إحداثيات داخل `if (BuildConfig.DEBUG)`.

### 6) ملفات جديدة فحصتها
**AppErrorLogManager** (متوسطة):
- `addLog` يقرأ ويكتب `_logs.value` بلا ذرّية (سباق بين الخيوط يضيّع سجلات).
- كل خطأ يُرسل إلى Crashlytics كاستثناء غير قاتل دون حد (إغراق وحصص).
- نصوص الأخطاء قد تحوي أرقام هواتف أو إحداثيات، وتُصدَّر في التقرير.
```kotlin
import kotlinx.coroutines.flow.update
import java.util.concurrent.ConcurrentHashMap

private val lastReported = ConcurrentHashMap<String, Long>()
private fun shouldReport(key: String): Boolean {
    val now = System.currentTimeMillis()
    val last = lastReported[key]
    return if (last == null || now - last > 60_000L) { lastReported[key] = now; true } else false
}
private val PHONE = Regex("\\+?\\d[\\d\\s-]{7,}\\d")
private val COORD = Regex("-?\\d{1,3}\\.\\d{4,}\\s*,\\s*-?\\d{1,3}\\.\\d{4,}")
private fun redact(s: String) = s.replace(PHONE, "[رقم]").replace(COORD, "[موقع]")

private fun report(defaultTag: String, type: String, tag: String, message: String, throwable: Throwable?) {
    val details = throwable?.stackTraceToString() ?: ""
    addLog(ErrorLogItem(tag = tag.ifBlank { defaultTag }, message = message, details = details, type = type))
    if (shouldReport("$tag:$message")) {
        try { MyApplication.instance?.recordExceptionSafely(throwable ?: Exception("$tag: $message")) } catch (_: Exception) {}
    }
}
fun logFirestoreError(tag: String, message: String, throwable: Throwable? = null) = report("Firestore", "FIRESTORE", tag, message, throwable)
fun logApiError(tag: String, message: String, throwable: Throwable? = null) = report("API", "API", tag, message, throwable)
fun logGenericError(tag: String, message: String, throwable: Throwable? = null) = report("General", "GENERAL", tag, message, throwable)

private fun addLog(item: ErrorLogItem) {
    val safe = item.copy(message = redact(item.message), details = redact(item.details))
    _logs.update { (listOf(safe) + it).take(MAX_LOGS) }       // ذرّي
}
```
وصِل أخطاء الخرائط به لتظهر في التشخيص: في `catch` الخاصة بـ Valhalla وOSRM والبلاطات استعمل `AppErrorLogManager.logApiError("Valhalla"/"OSRM", ...)` و`logGenericError("Tiles", ...)`، وفي `MapDiagnosticsDialog` اعرض آخر 5 سجلات.
**PermissionManager:** ما ذكرته في البند 2. **ConflictResolver:** سليم للإصدارات؛ ثغرة صغيرة: لا يكشف التعارض إن تساوى `localVer == cloudVer` واختلفت البيانات (تعديلان متزامنان بلا رفع الإصدار) — اعتبره تعارضاً إن اختلف `updatedAt`.
